# DR02 二阶段 IK 调试记录

## 结论

最初的每帧二阶段实现会明显劣化 Eagle Claw 的手臂姿态，根因不是单一
`coarse.ik_match_table` 权重没有调准，而是它与本项目的“上一数据帧”时间
连续性和整帧速度硬约束在时序上冲突。采用 **仅首帧 coarse-to-fine 初始化**
并在粗优化前以 `hips_mean` 初始化 floating root 的 xyz/yaw 后，后续帧回到
原有单阶段时间约束路径，消除了该冲突。

## 症状与假设

`MA_Eagle_Claw_Fist_2.csv` 的开头手臂出现扭曲。原实现把 GMR 风格的粗优化
应用到每一帧；粗优化不含 `PostureTask` 或 `FrameVelocityLimit`，却在细优化前
改变了同一 `Configuration`。细优化的速度盒仍以粗优化前的上一帧为锚点，导致
手臂关节的可用帧预算已经被粗解消耗，容易产生不自然的边界解。

曾尝试只投影 coarse 解中被速度限制的切空间分量到预算盒。该 partial projection
不是严格的姿态优化：它会保留未限制关节和浮动根的 coarse 位移，却裁剪肩/肘的
协同位移，破坏末端链的几何一致性。因此“链投影/全局投影”虽能满足速度预算，
仍不如正确的首帧初始化稳定。

## 当前语义与参数边界

- `application` 目前只接受 `first_frame_only`。第 0 帧：可选 root 初始化 →
  coarse FrameTask + ConfigurationLimit → 正常 fine FrameTask/接触任务；第 0
  帧不添加 PostureTask 或 FrameVelocityLimit。
- `initialize_root_from_target` 使用目标四元数的 yaw；输入 PKL 和 MuJoCo 使用
  `wxyz`，转换为 SciPy 的 `xyzw` 后提取 yaw。为了保持机器人直立，roll/pitch
  强制为零。
- 第 1 帧起完全走既有单阶段路径，并将第 0 帧最终姿态作为 temporal/FVL 锚点。
  因而速度约束覆盖 frame1+ 的完整数据帧；首帧没有“上一数据帧”，不定义该预算。
- 粗权重仍为当前 DR02 测试选择：头与肩方向 100，普通方向 10，脚位置 50，手位置
  10。它们是 GMR 论文任务设计与 DR02 可用链路的近似对应，不能视为通用最优权重。

## 25 动作 QA 计划与判据

对 `command.md` 列出的 25 条动作，以相同生成的 target PKL 分别运行基线和策略 B，
再使用 `compare_dr02_retarget_quality.py` 输出 JSON/CSV。通过判据：两组均应有限、
无关节限位违规、候选 frame1+ 无速度预算违规；候选前100帧四末端误差不得明显高于
基线，并优先选择全轨 fine-task/末端误差降低的配置。对“误差改善但视觉仍异常”的
动作，还应使用并排 MuJoCo 回放检查贴限持续时间与自碰趋势。最终 25 条汇总将在
批量 QA 完成后补入本节。
