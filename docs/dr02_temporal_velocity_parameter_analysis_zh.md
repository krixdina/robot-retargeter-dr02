# DR02 时间连续性 / 速度参数分析（匹配重跑）

运行日期：2026-09-01。本版替换此前使用历史 B0 和名称前缀分组的分析。所有候选方案都在相同的 25 条完整、未截帧 MotionDecode 动作上，用当前代码和冻结 PKL 重新运行。

## 结论

**有条件的软件测试选择：B2（`cost=10`、肩部 `8 rad/s`、肘部 `8 rad/s`）。** 在肘部上限不高于 8 rad/s 的候选中，它有最佳的四末端和上肢跟踪折中。B3 是更保守的肘部备选；B4 跟踪略好，但允许肘部达到 10 rad/s。本结论不是硬件安全建议：所有候选仍有很长的 hard 限位连续段，且 B2--B5 的有限差分加速度峰值仍为 1920 rad/s²。

## 现在的 B0 是什么

B0 是**匹配的无约束基线**，不再是旧的历史 QA CSV。对于每一条冻结 PKL，它与 B1--B5 使用同一 DR02 模型、任务权重、接触处理、120 Hz、求解器和源动作，只关闭：

```yaml
two_stage_optimization: {enabled: false}
temporal_continuity_regularization: {enabled: false}
inter_frame_velocity_limit: {enabled: false}
```

所以 B0 到 Bx 的差异是本次时间/速度参数的受控比较。B0 没有配置速度预算，因此 `edge %` 有意标记为 N/A。

## 已校正的跟踪指标

旧报告错误采用名称前缀分组：所有 `left_*` body 都进入 `left_arm`，右侧同理。这会混入腿和手臂，并把手重复计算。旧的 `track P95` 和 `rot P95` 都受此影响；本版不再使用它们。

现在每帧都用显式的一对一 PKL→DR02 FK 映射评估。每个动作的组分数是组内各 pair 的 P95 算术均值；表格再对 25 条动作求均值。P95 是该 pair 逐帧误差的第 95 百分位数：约 95% 帧的误差不高于它，约 5% 更差。最终组分数是“P95 的均值”，并不是把全部样本合并后的总体 P95。

| 组别 | 显式映射 |
|---|---|
| 四末端（4EE） | `left_fore_arm→left_hand_link`、`right_fore_arm→right_hand_link`、`left_foot_end_link→left_foot_end_link`、`right_foot_end_link→right_foot_end_link` |
| 上肢（UL） | `left/right_shoulder→left/right_shoulder_x_link`、`left/right_arm→left/right_elbow_link`、`left/right_fore_arm→left/right_hand_link` |

位置误差是 FK 与 PKL 的欧氏距离（cm），姿态误差是两个四元数的最短夹角（度）。四末端组检查手/脚落点；上肢组可暴露“手恰好到位、肩或肘却走到怪异 IK 分支”的情况。

## 限位、运动与聚合指标

`near` 指相关关节距离任一有效关节限位不超过 5°；`hard` 指不超过 0.001 rad（约 0.057°）。`near/hard frame %` 是至少一个相应肩部或肘部关节满足该条件的帧比例；`hard run` 是连续 hard 帧的最长区间，单位为帧。表格同时保留 near 和 hard，避免将 5° 预警区静默删除。

`qdot P95` 和 `qddot P95` 分别是肩/肘有限差分速度（rad/s）和加速度（rad/s²）的绝对值 P95。`edge %` 是肩/肘速度样本达到其配置上限 99% 以上的比例。`arc / B0` 是四末端 FK 轨迹长度相对 B0；`range / B0` 是肩/肘/腕平均关节活动范围相对 B0。两个比例理想目标是接近 1，而非无限增大。↓ 表示通常越小越好；↑ 表示越接近 1 越好。`qdot` 没有箭头，因为速度过低（冻结）和过高（尖峰）都不好。

“动作等权”是主要聚合方式：先对每条动作计算指标，再对 25 个值做普通平均。因此短的体育动作和 14,146 帧的跑步动作各有一票。

## 校验与局限

独立 FK 审计从每个保存的 qpos CSV 和冻结 PKL 直接重新计算四末端与上肢指标，且没有调用报告评价器。它检查了 150 个候选-动作行，全部通过；报告值与审计值最大绝对差为 0.0（容差 `1e-9`）。逐行审计和摘要见 `docs/data/dr02_temporal_velocity_matched_independent_audit.csv` 与 `docs/data/dr02_temporal_velocity_matched_independent_audit_summary.json`。

这些只是运动学 IK 结果，未验证碰撞、力矩/电流、控制器跟踪、加速度/jerk 整形、热限制、负载或硬件安全。长 hard 限位连续段和残余加速度峰值意味着部署前仍需要进一步可行性工作。
